# SKILL PROPOSALS — skill-miner run 2026-07-02

Source: 81 sessions inventoried; 13 transcripts sampled across 5 clusters
(context reconstruction, mail/bridge, QA/verification, deploy/fix, projectmd repeats)
via 3 parallel Sonnet subagents (~200K subagent tokens, near-zero main-session cost).

## Validation of existing work

The dominant pattern in the QA/deploy clusters is **premature "done"**: code changed,
tests green, "arc closed" declared — then a terse user correction ("no sold tag")
or the next session reveals it broken. The sold-cascade defect survived SIX deploys
this way. This independently validates `auditor-general` (built today): FIX VALIDATION
mode exists precisely for this. No duplicate proposal needed — deploy it and use it.

---

**PWA-VERIFY** — Category: RECURRING FAILURE / REINVENTED WHEEL

**Problem:** The device-side verification loop after every CarMatch/AVT deploy is
fully manual and re-improvised each time: hard-reload PWA / force-close to bust the
service-worker cache, tap through the flow, screenshot, relay, agent calls pass/fail.
Appeared near-identically in 3 of 6 QA/deploy transcripts ("CarMatch unified inbox QA",
"E2E verification", "sold cascade defect"). Stale SW bundles repeatedly masked whether
a fix landed — the root enabler of the six-deploy defect.

**Proposed skill:** Codified post-deploy device verification protocol: cache-bust
checklist (force-close, SW bundle version check), per-fix verification steps generated
from the deploy diff, screenshot-relay sequence (pairs with qa-mirror when at desk),
explicit VERIFIED / UNVERIFIED verdict per fix written back to the session.

**Trigger phrases:** "verify the deploy on device", "did the fix land on the phone",
"pwa verify", "bust the cache and check", "runtime verify this".

**Value:** 3+ sessions/week touch this loop; eliminates the single most expensive
failure class found (defects surviving multiple deploys behind stale caches).

**Complexity:** MEDIUM. **Build priority:** IMMEDIATE.

**Value:** small each, but they fire weekly and cost one publish cycle total.

**Complexity:** LOW. **Build priority:** IMMEDIATE (bundle into next publish).

**CONTRACT-MAP** — Category: CONTEXT TAX / REINVENTED WHEEL

**Problem:** Cross-project facts get re-derived: extractor source location took 3
escalating `find` commands; CarMatch/AVT cross-project function contracts
(`createConversation`, `sendMessage`, `getMarketValue`, `matchCreated`,
`listingPublished`, `receiveDemandSignal`), function counts (18/3 codebases, 43-in-one-file)
re-anchored in multiple sessions. These span repos, so no single CLAUDE.md owns them.

**Proposed skill:** Canonical cross-project contract registry (like
`inbox-registry.md`): one generated FACTS/CONTRACTS file per ecosystem pair
(AVT<->CarMatch first), harness-loaded via CLAUDE.md pointer, regenerated by script
so it can't drift — plus a skill that answers "where does X live / who calls Y"
from it instead of grepping cold.

**Trigger phrases:** "where does X live", "what functions connect AVT and CarMatch",
"contract map", "who calls this function", "project facts".

**Value:** kills the highest-frequency CONTEXT TAX in build sessions (multiple
rediscovery turns per session across the deploy cluster).

**Complexity:** MEDIUM. **Build priority:** SOON.

**MOUNT-PROTOCOL ROLLOUT** — Category: RECURRING FAILURE (action, not a skill)

**Problem:** Both "ProjectMD auditor" repeat sessions died on unmounted folders —
stop-and-ask, zero work done. A continuity-seed session explicitly admits the auto
mount-check is "a behavioral instruction, not a hard trigger" and only SKILL MAKER's
CLAUDE.md carries it.

**Proposed action:** Copy the "Auto session protocol" block into every active
project's CLAUDE.md (the block is already written portable). Optionally investigate
Cowork SessionStart hooks for a hard-gate version — one sampled session
("SessionStart hook marker") suggests this was already being probed; check its outcome
before duplicating work.

**Value:** 2 dead sessions in sample; each unmounted start is a full wasted session.

**Complexity:** LOW. **Build priority:** IMMEDIATE.

**SCHEDULED OVERSIGHT** — Category: RECURRING FAILURE (automation of existing skill)

**Problem:** The extractor audit found 3/5 scrapers never scheduled, VMC pagination
pulling 1 listing instead of hundreds, empty Pub/Sub consumers, and 0-listing runs
passing silently — "20% of potential data coverage" undetected until a manual audit.
Silent degradation has no watcher outside Herald.

**Proposed action:** Scheduled task per critical system (extractor first) running
`auditor-general` SYSTEM OVERSIGHT mode weekly; verdict posted to the project inbox
via agent-bridge. No new skill — composition of two existing ones plus a schedule.

**Value:** converts the one-off audit that found the 80% coverage gap into a standing
detector.

**Complexity:** LOW. **Build priority:** SOON.

## Known limits of this run

Transcript reads returned session TAILS (limit 25), so session-start context tax is
under-measured — the continuity cluster's true cost is likely higher than evidenced
here. Session titles proved unreliable (one "continuity seed" session was actually
Agency banner work), so title-based clustering has noise. Neither limit changes the
top-3 ranking; both would only strengthen the CONTEXT TAX proposals.
